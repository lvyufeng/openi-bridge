任务产物落库 + issue 编辑 + 通知 端到端实测记录（2026-10-16）
============================================================

一、任务产物导出（openi_task_export_to_dataset / _to_model / _progress）

在 scratch-repo 仓里放一个 train.py：用 c2net.context.prepare() 拿 output_path，
写 metrics.txt 与 ckpt/model.bin，再 upload_output()。用 openi_start_task 开 TRAIN 任务
TASK-12（GCU / ENFLAME-T20，spec 229），约 30 秒到 SUCCEEDED；输出文件约两分钟后才被平台
索引出来（openi_task_output_files 的 file_list 从空变成两条，FileName 即
"ckpt/model.bin" 与 "metrics.txt"）。

导出到数据集（先 openi_create_dataset 建 scratch-repo）：

    POST /ai_task/export2dataset?dataset_id=<uuid>&id=TASK-12
    body: task_id=TASK-12&file_list_str=metrics.txt,ckpt/model.bin
    -> 200 {"code":0,"msg":"ok","data":{"id":"dataset:<uuid>:export_task:TASK-12:process_id"}}

    GET /dataset/get_export_process?id=dataset:<uuid>:export_task:TASK-12:process_id
    -> {"ckpt/model.bin":100,"metrics.txt":100}   （100 完成；0 刚开始；-1/-2/-3 失败）

导出后 /dataset/files?dataset_name=scratch-repo 里能看到 ckpt/ 目录与
metrics.txt，说明产物已经脱离任务、落进数据集。关键点：这个接口只认表单体，JSON 体会被
反向代理 403；清单字段必须叫 file_list_str，写成 file_list 平台回 "file list is empty"。

导出成模型库（scratch-repo）：

    POST /ai_task/export2aimodel?id=TASK-12
    body: name=...&alias=...&owner_id=248&aimodel_type=0&is_private=false&engine=0&
          label=&license=MIT&task_id=TASK-12&file_list_str=ckpt/model.bin
    -> 200 {"code":0,"msg":"ok","data":{"id":"a512271f-...","name":"scratch-repo",
            "owner_name":"<account>","process_id":"ai_model:a512271f-...:export_task:TASK-12:process_id"}}

    GET /aimodel/get_export_process?id=ai_model:a512271f-...:... -> {"ckpt/model.bin":100}

英文名全平台唯一，重名返回 {"code":4003,"msg":"Model English name already exists"}。

二、issue 编辑（openi_update_repo_issue）

在 scratch-repo 里 openi_create_repo_issue 建 issue #1，然后：

    POST /repos/scratch-repo/issues/1  body {"state":"closed"}  -> 201，state 变 closed
    POST .../issues/1  body {"state":"open"}                                   -> 201，state 变 open
    POST .../issues/1  body {"title":"e2e update probe final"}                 -> 201，标题随之改变
    POST .../issues/1  body {"body":"new body"}                                -> 201，正文随之改变

Gitea 原生的 PATCH /repos/{o}/{r}/issues/{n} 在这套部署上被前置反向代理挡成空 400（text/html），
PUT 与带 _method=PATCH 的 POST 都 404，所以编辑只能走 issue 路径上的 POST + JSON 体。

三、通知（openi_notification_detail / openi_mark_all_notifications_read）

    GET  /notifications/threads/{id}          -> 200（本条通知的完整内容，id 不存在时 404）
    GET  /notifications/threads/{id}/comments -> 通知线程里的评论正文
    PUT  /notifications?all=true              -> 205（全部标已读）

当前账号通知数为 0（list count=0、unread=0），threads/1 返回 403（存在但不属于本账号）、
threads/999999999 返回 404，两条都证明 GET 路由是活的。单条标已读没有可用接口：
PATCH 被反代拦截、PUT 与 POST(_method=PATCH) 均 404（见 README 的已知限制）。
